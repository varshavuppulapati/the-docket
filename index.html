How This Is Different From a Chatbot

It uses a language model. It is not a conversation, and that distinction is the whole design.

Five narrow agents, not one general one

A chatbot is a single model answering whatever you type next, holding the whole conversation in its head. The Docket instead runs a fixed pipeline of five specialists, each with one job and a system prompt scoped to exactly that job. None of them can see or influence a step that isn't theirs.

1. Intake — extraction 2. Code Research — retrieval 3. Compliance — narration only 4. Drafting — the letter 5. Execution — the workflow

The model never does the math

Every pass/fail determination is plain deterministic JavaScript checked against the embedded zoning code — auditable, and the same answer every time for the same inputs. The language model's job is narrower than it looks: it extracts, it searches, it explains in plain English, and it drafts. It is never the thing deciding whether a setback of 9 feet against a 15-foot minimum passes.

It asks — structurally, not conversationally

When the Intake Agent can't find something the compliance check actually needs (a lot area, a footprint, an existing coverage figure), the pipeline stops and asks for exactly that field, as a form, not as a follow-up chat message. You fill it in, review resumes exactly where it paused. There's no back-and-forth to interpret — just the missing inputs, named.

You can watch it reason

Every live agent card has a "View agent detail" toggle exposing the model's actual reasoning trace alongside its raw output — not a fabricated explanation, the real chain of thought Groq returns for that call. A chatbot gives you an answer. This shows the work.

It acts, and it remembers

The last step isn't a reply — it's a workflow. The Execution Agent assigns a case number, then actually branches on the outcome: an approval gets a calculated fee, a downloadable permit record, and a final inspection scheduled ten business days out as a real .ics calendar file; an escalation gets routed to the correct reviewer queue with a priority level, a response deadline, a downloadable routing packet, and a calendar reminder for that deadline. Every one of those is a real, separately downloadable artifact, not one generic "case filed" message — and the whole sequence is then filed into a persistent Case Queue you can search later. No message ever gets sent anywhere on its own; every file is a local download you choose to use. A chatbot forgets you the moment the tab closes. The Docket runs the workflow and keeps the file.
